The Lexicon

Every mathematical term this project uses is defined exactly once, in its own shard under definitions/. The results, the lab book, and the proof workspaces reference a definition by id; they never restate it. Two shards claiming the same term or alias is not a style complaint, it is a build failure — the check that enforces it runs on every commit. That is the whole point of this layer: a definition that drifts between two files is an error class no proof checker ever sees.

Status is shown as the shard's own: locked (signed off, and the reference frozen) or draft (in use, not yet ratified — a draft definition is not a licence to treat anything resting on it as settled). Provenance is likewise the shard's own: cited definitions are byte-matched to a local published source, consensus are adopted, and original are introduced here.

Bodies are shown as the shard's own source text, LaTeX and all: this site carries no mathematics renderer, so \(…\) and \[…\] appear verbatim rather than typeset. Reading the raw shard is the same experience as reading the repository, which is the intent — nothing is re-worded on the way to the page. Cross-references of the form [[def-slug|text]] are the repository's internal links.

The process glossary

The lexicon above is mathematical vocabulary. The project also runs on a working jargon — T0, banking, waves, arms, balloons, the rigour rungs — and that has exactly one canonical home too: GLOSSARY.md. The entries are listed here by name and linked there rather than copied: one canonical source per term is the same rule that governs the shards, and a glossary duplicated onto a web page is a glossary that will drift.
